# Format-3 fuzz smoke targets

These targets are opt-in and are not collected by pytest. They implement a
bounded smoke run; they are not a long-running campaign.

`r3g_libfuzzer.cpp` calls the C++ codec directly with no Python validator in
front. It accepts the `.case` records generated by
`tests/format3_native_cases.py`, which contain one block and its run slice, and
also accepts arbitrary bytes. It bounds output allocation to 64 rows. Each
input runs through the forced scalar and host SIMD paths; refusal statuses and
successful outputs must match. The existing `tests/test_format3_native.py` and
`tests/format3_native_cpp.py` conformance checks compare decoded data with
`reference.decode_block` and the committed digests, including width-16 wrap
vectors. Thus a successful scalar result is anchored to the reference oracle,
while the fuzzer checks scalar/SIMD agreement for mutated inputs.

Build the standalone target with the host path used by the fixture test:

```bash
CPU_SRC=src/roshambo3/backend/_cpu_src
clang++ -std=c++17 -O1 -g -march=x86-64-v3 \
  -fsanitize=fuzzer,address,undefined -fno-sanitize-recover=all \
  -fno-omit-frame-pointer -I "$CPU_SRC" \
  tests/fuzz/r3g_libfuzzer.cpp \
  "$CPU_SRC/r3g_codec.cpp" "$CPU_SRC/r3g_unpack_scalar.cpp" \
  "$CPU_SRC/r3g_build_scalar.cpp" "$CPU_SRC/r3g_build_avx2.cpp" \
  "$CPU_SRC/r3g_encode.cpp" "$CPU_SRC/r3g_unpack_avx2.cpp" \
  -o /tmp/r3g_libfuzzer
python tests/format3_native_cases.py write /tmp/r3g_seed_cases
mkdir -p /tmp/r3g_crashes
/tmp/r3g_libfuzzer /tmp/r3g_seed_cases -max_total_time=60 \
  -max_len=1048576 -artifact_prefix=/tmp/r3g_crashes/
```

On Linux aarch64, use `-march=armv8-a+simd` and
`r3g_unpack_neon.cpp` and `r3g_build_neon.cpp` in place of the x86 flag and AVX2 sources. The target
runs only the ISA compiled into that host build; the CI CPU tests separately
force and verify scalar plus NEON on Linux arm64.

The Python target is seeded with recipes for shape/color conformance corpora
and committed adversarial corpora. A recipe selects one whole corpus, copies it
to a temporary directory, and optionally mutates one file. It then runs
validator `open`, validator `scan`, and native decoding of every block, with a
bitwise comparison against the reference. `CorpusValidationError` is the
expected refusal; unexpected exceptions and native/reference disagreements
escape as failures. Set `ROSHAMBO3_FUZZ_TIMINGS` to a JSONL path to record each
input's duration and outcome.

For fuzz mode, Atheris imports `roshambo3` under its import hook and instruments
the seed-mutation and entry-point functions. The `--write-seeds` and `--smoke`
modes do not require Atheris; `--smoke` imports the reader normally. The
definition target uses the same import-time instrumentation for `roshambo3`
and instruments its input adapter, while keeping the seed writer dependency-free.

```bash
python tests/fuzz/python_corpus_fuzzer.py --write-seeds /tmp/r3g_python_seeds
ROSHAMBO3_FUZZ_TIMINGS=/tmp/r3g_python_times.jsonl \
  python tests/fuzz/python_corpus_fuzzer.py /tmp/r3g_python_seeds \
  -max_total_time=60 -artifact_prefix=/tmp/r3g_python_crash_
```

The definition target uses curated case-mixed, continuation, `!Name`, nested
reference, and long-chain examples plus the bare `definition.json` seeds. It
calls only `reference.check_definition_text`; it never imports RDKit. Its
accepted outcomes are a summary or `value.definition` / `limit.definition_*`.
Set `ROSHAMBO3_DEFINITION_FUZZ_TIMINGS` to retain per-input timings.

```bash
python tests/fuzz/definition_fuzzer.py --write-seeds /tmp/r3g_definition_seeds
ROSHAMBO3_DEFINITION_FUZZ_TIMINGS=/tmp/r3g_definition_times.jsonl \
  python tests/fuzz/definition_fuzzer.py /tmp/r3g_definition_seeds \
  -max_total_time=60 -artifact_prefix=/tmp/r3g_definition_crash_
```

The Python targets require the worktree's editable CPU extension and `atheris`
for fuzz mode. `--smoke SECONDS` runs one bounded pass over the seed recipes
without importing atheris. Their elapsed time is recorded per input; the 20 s
open-tier limit remains a best-effort observation, not a harness assertion.
The `format3-fuzz-smoke` CI job runs each of these three targets for 60 seconds
and uploads the seed corpora, logs, timings, and any libFuzzer crash artifacts.
